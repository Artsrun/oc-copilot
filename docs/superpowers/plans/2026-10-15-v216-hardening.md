# v216 Read-only Boundary Hardening Implementation Plan

> Superseded by `2026-10-15-v216-rechecked-cleanup.md`. The recheck reproduced the Git-helper write through real OpenCode and found that the proposed deny-only map needs changing: its marker must precede the final catch-all deny so the shell tool is withheld.

> **For agentic workers:** Execute inline, task-by-task, following repository AGENTS.md. Steps use checkbox (`- [ ]`) syntax for tracking. Review and plan only have been completed; implementation steps below are pending.

**Goal:** Release 0.0.216 with a defensible read-only boundary, accurate enforcement notices, and a green release gate.

**Architecture:** Keep process configuration in `src/enforce.ts`, process ownership in `src/net.ts`, and session rules in `src/server-session.ts`. For this release, deny arbitrary shell execution on enforced agents and use existing read/search tools plus gitScan for inspection. Carry actual enforcement evidence with each turn instead of deriving notices from window-global state.

**Tech Stack:** Strict TypeScript, VS Code extension API, plain Node boundary suite, real OpenCode 1.x scripted-model probes, vsce.
